# Persona Loading + Routing Implementation Plan (permissions §4 personas)

> **For agentic workers:** REQUIRED SUB-SKILL: subagent-driven-development. Checkbox steps.

**Goal:** Load custom agent personas from `~/.hadron/agents/` + `<repo>/.hadron/agents/` (front-matter `name` + `preferred_role`), and make `@persona-name` route like `@preferred_role` (reusing WS4§4 role routing).

**Architecture:** A `Persona` type + `load_personas` reusing the skills loader's front-matter helpers; the router resolves a persona-name token to a seat carrying its `preferred_role`.

**Tech Stack:** Rust (hadron-gluon). cargo test.

## Global Constraints
- Baseline gate before/after: `cargo test --workspace --features gui` (full).
- INERT session: cargo test/check only, never run binaries; tempdirs; never touch real `~/.hadron`. **Load path is injected (like the skills global dir) so tests stay hermetic.**
- Back-compat: no personas dirs ⇒ routing behaves exactly as WS4§4 today.
- Reuse the skills loader's `split_front_matter`/`front_matter_value` (skills.rs) — no second YAML splitter. Reuse WS4§4's role matching — a persona resolves to a role, then the existing role→seat logic applies.
- Precedence: a persona name never shadows a real quark id or a reserved alias (`@team`/`@orchestrator`) — those win, same as roles.
- One focused commit per task.

### Task 2: `@persona-name` routes via `preferred_role` (router + engine)

**Files:** `crates/hadron-gluon/src/router.rs` (thread personas into resolution), `crates/hadron-gluon/src/engine.rs` (load personas + pass them; injected dir like skills), tests inline.

**Design:** `match_longest_mention` gains a `personas: &[Persona]` param. Resolution ORDER (after id + `@team`/`@orchestrator` + role, so those keep precedence): a token matching a persona `name` (case-insensitive) resolves as if it were that persona's `preferred_role` — i.e. find the first enabled card carrying that role (reuse the role pass's logic; a persona with no `preferred_role`, or whose role matches no seat, falls through softly). Thread `personas` through `human_mentions`/`parse_addressee` and their callers; the engine passes the loaded personas.

- [ ] **Step 1: Study** how WS4§4's role pass resolves a role token to a card (`match_longest_mention`, the `card.roles` scan). The persona pass reuses that: persona name → preferred_role → same role→card scan.
- [ ] **Step 2: Failing tests** (extend the `roster()` helper; add a `personas()` helper): `persona_routes_to_a_seat_with_its_preferred_role` (persona `security-reviewer`/`security`, a card with role `security` → `human_mentions("@security-reviewer go", roster, personas)` → that card's id); `persona_with_no_matching_seat_falls_back_softly` (→ `[]`, no panic); `id_and_alias_beat_a_persona_name` (a card id or `@team` named the same as a persona wins); `persona_match_is_case_insensitive`; `no_personas_is_todays_routing` (empty personas → identical to WS4§4).
- [ ] **Step 3: Run — expect FAIL.**
- [ ] **Step 4: Implement.** Add the persona pass to `match_longest_mention` (gated behind id/alias/role precedence). Thread `personas: &[Persona]` through `match_longest_mention`, `human_mentions`, `parse_addressee` (and `task_names_card_specifically` if a persona should count as specifically-naming — decide + document; default: a persona name is a specific address of the resolved card). Update all call sites. In the engine, `load_personas(user_hadron_dir()/agents [injected], workspace_root/.hadron/agents)` once per projection (mirror skills) and pass to the router calls. Char-boundary safety: ride the existing `boundary_match`/`try_match` — no new matcher.
- [ ] **Step 5: Run** tests + full gate.
- [ ] **Step 6: Commit** — `git commit -m "feat(gluon): @persona-name routes via preferred_role (reuses role routing)"`
